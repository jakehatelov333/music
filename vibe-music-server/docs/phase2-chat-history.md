# 第二批：完整聊天历史、模型窗口与会话并发

## 数据模型和升级

上线前先执行 `sql/phase2_chat_migration.sql`。迁移创建 `ai_chat_state`、给完整历史补充会话/消息 ID 索引；新安装若没有聊天表则一并创建。可重复运行，不删除、不改写 `chat_messages` 的旧记录。本机开发数据库已执行并复验迁移，详情见 `phase2-business-foundation.md`；其他环境仍需先迁移。

- `chat_messages`：按事件追加的完整历史。`USER`、`ASSISTANT`、工具请求和工具结果各只追加一次。系统提示词不保存。原始消息 ID、创建时间不会随窗口裁剪改变。历史和分页均以自增 ID 排序，消除同一秒内消息顺序不确定的问题。
- `ai_chat_state.context_json`：独立的模型上下文，最多 20 条消息，不包含系统提示词。工具请求/结果按 LangChain4j 原生格式序列化，AI 消息同时含文本和工具请求时不会丢失两者的对应关系。
- 每次 LC `ChatMemory.add` 将当前窗口更新与新历史追加放在同一数据库事务。窗口加载不走追加路径；模型上下文淘汰消息不会删除历史。失败请求已接收的用户输入和已完成的工具事件会留在历史中。
- 旧会话第一次生成时，最多读取最近 40 条旧记录初始化 20 条窗口，旧历史继续保留。旧版本此前已物理删除的历史无法恢复。损坏旧工具记录或未完成的工具交换不会用于模型回放；原始历史不受影响。

## 并发与清空行为

同一会话同时只允许一个生成请求。阻塞生成、SSE 生成与清空使用同一个 MySQL 会话行租约，不依赖 Java 进程内锁，因此多个后端实例也适用。请求繁忙时返回 HTTP 409 和提示“当前会话正在生成回复，请结束后再操作”；其他会话可继续生成。

租约使用随机运行 token 与数据库时间，持续请求超时上限再加 2 秒。模型调用期间不持有数据库事务或连接。每次窗口更新先检查 token 与有效期并锁定会话行，然后追加历史。释放租约也校验 token，已超时的旧请求不能释放后续请求的租约，也不能向清空后的会话写入迟到数据。进程崩溃时最多等待租约到期即可恢复。

请求成功、错误、执行队列拒绝、任务超时、SSE 客户端断开时均关闭本次预算和窗口。窗口写入与关闭在同一个请求对象上同步，关闭返回后不再允许旧对象写入。若释放租约时数据库暂不可用，关闭仍然完成并等待租约自然过期。

清空在同一事务内重置窗口为空数组、删除该会话完整历史并释放租约。生成期间的清空返回 409；用户需要在回复结束或取消后重试。清空成功后，随后新请求不能回放旧记录。

## 内存与现有限制

每个请求只持有一个最多 20 条的窗口；没有随会话数量增长的全局内存映射。请求结束后窗口随本次运行释放。数据库历史不设置自动过期或自动删除策略。

现有 API 路径保持一致。`GET /ai/chat/history` 返回完整历史；大量记录应使用 `/ai/chat/history/page` 或 `/ai/chat/recent`。第一批的身份绑定、输入/输出限制、工具预算和统一错误响应继续生效。

LangChain4j 0.36.2 对已经发到供应商的请求仍缺少可靠的取消接口；关闭会停止应用输出、后续模型/工具轮次及历史写入，已发送请求仍可能完成并计费。此批不增加写工具或 Agent 确认执行协议。

## 回归测试

`AiAssistantFactoryTest` 使用真实 LangChain4j 编排、模拟模型和模拟持久化，验证跨运行上下文、超出窗口后的完整历史和稳定 ID、系统/工具消息不重复、工具预算、SSE、迟到回调、旧数据初始化、未完成工具交换过滤。

`AiConversationPersistenceTest` 使用独立 H2/MySQL 模式数据库、真实 MyBatis 和 Spring 事务，验证同会话并发抢占、跨会话隔离、活动期间拒绝清空、旧 token 不能写入/解锁新租约，以及追加失败时窗口和整批消息共同回滚。H2 验证不替代上线前在 MySQL 上执行迁移与部署验收。

`AiControllerSecurityTest` 保留第一批归属校验、非法参数、错误脱敏、限流和超时回归。
